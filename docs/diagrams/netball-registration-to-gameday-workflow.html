SportsBB Administrator · Current-state data workflow

From team registration to the public scoreboard

A complete view of who enters data, where it is approved, what stays private, how match-day actions become scores and time, and which public and broadcast channels receive the result.

The API-backed workflow already exists.Registration, accreditation, team sheets, the match event ledger, public feeds and derived standings are connected through the main database.
The open GameDay demo is separate./gameday-demo currently synchronizes only between browser tabs using local storage. It is safe for testing but is not yet the real public-data path.

Flow 01 · Registration and match preparation

Private registration becomes approved competition data

Registration approval publishes only the team identity. Roster accreditation is a second gate that publishes a limited squad view. Sensitive evidence remains inside the tenant-protected registration boundary.

Flow 02 · Internal scoring to public output

Every match-day action writes once; public channels read a safe projection

The match event ledger keeps the operational history. The match row carries the current score, status, period and clock snapshot. A read-only public database role exposes only approved public tables and views.

Important: the current demo is not this flow

/gameday-demo writes gameday.capture-demo.state.v1 to browser local storage and uses a BroadcastChannel. It never calls the GameDay API, never writes match_event, and cannot update the real website or broadcast feed.

Safest integration point

Keep registration untouched. Replace the demo’s browser storage adapter with authenticated GameDay commands, then make the public audience screen consume the existing read-only broadcast JSON feed.

Current gap and recommended build order

The workflow is sound; the staffing and demo integration are unfinished

Current staffing limitation

  • One account can hold only one match assignment.
  • Exactly one account can occupy each official role.
  • The readiness gate requires supervisor, scorer, timekeeper, statistics/lineup and result approver.
  • This prevents one person from combining score and clock, and prevents separate Team A and Team B scorers.

Low-risk sequence

  • Add match-specific duties and staffing templates only to the GameDay domain.
  • Connect the local scorer UI to the guarded API in a local database first.
  • Connect the audience screen to /public/broadcast/matches/:id/live.json.
  • Test solo operator, scorer + timekeeper, and two scorers + timekeeper.
  • Deploy additive changes with existing matches defaulting to the current full-crew policy.
