Section 1

How to use this profile

Fixed

Infrastructure rules

These are the defaults for every project: Debian 13, ISPConfig, the selected Apache or Nginx engine, GitHub, site-owned files, managed TLS, Supervisor for persistent Node processes and no Docker.

Per project

Deployment variables

The AI must collect repository, domain, ISPConfig IDs, site user, runtime, ports, database, storage, email, backup and release values.

Required output

Generated runbook

The AI must produce commands with placeholders, preflight gates, deploy-key setup, managed Apache configuration, acceptance tests and rollback.

Never include

Live secrets

This profile and generated templates must never contain real passwords, tokens, private keys, session secrets or personal production data.

Instruction to the receiving AITreat fixed values as infrastructure policy. Do not silently replace them with Docker, Caddy, cloud-only hosting or a different control panel. Require the project to choose Apache or Nginx and generate only that track. If a project genuinely requires an exception, label it clearly and obtain approval.

Section 5

Required ISPConfig file layout

/var/www/clients/<ISPCONFIG_CLIENT_ID>/<ISPCONFIG_WEB_ID>/
├── web/
│   └── <PROJECT_SLUG>/
│       └── source/                 # Git checkout; application runs here
├── private/
│   └── <PROJECT_SLUG>-shared/
│       └── .env                    # real secrets; mode 0600
└── home/
    └── .ssh/
        ├── <PROJECT_SLUG>_prod     # private deploy key; never shared
        └── <PROJECT_SLUG>_prod.pub # public key; add to GitHub
export SITE_ROOT=/var/www/clients/<CLIENT_ID>/<WEB_ID>
export APP_ROOT="$SITE_ROOT/web/<PROJECT_SLUG>"
export SHARED_ROOT="$SITE_ROOT/private/<PROJECT_SLUG>-shared"
export SSH_DIR="$SITE_ROOT/home/.ssh"
Public-tree controlThe ISPConfig site root is normally owned by root. Never place .cache directly under it. Keep writable caches under $APP_ROOT/.cache, owned by the site user and its actual group. Although the application checkout must live in the ISPConfig web tree, Apache must proxy public traffic to the intended runtime or expose only a framework’s approved public build directory. Add managed Apache denial rules so repository source, .git, environment links, logs and internal files can never be downloaded directly.

Section 6

Standard GitHub deploy-key workflow

  1. Generate the key on the production server

    install -d -o "$SITE_USER" -g "$SITE_GROUP" -m 0700 "$SSH_DIR"
sudo -u "$SITE_USER" -H ssh-keygen -t ed25519   -C "<PROJECT_SLUG>-production-deploy"   -f "$SSH_DIR/<PROJECT_SLUG>_prod" -N ""
chmod 600 "$SSH_DIR/<PROJECT_SLUG>_prod"
chmod 644 "$SSH_DIR/<PROJECT_SLUG>_prod.pub"

  2. Print only the public key for handoff

    cat "$SSH_DIR/<PROJECT_SLUG>_prod.pub"

    The output begins with ssh-ed25519. The private file without .pub never leaves the server.

  3. Add it to the one repository

    GitHub → repository → Settings → Deploy keys → Add deploy key. Use a descriptive production-server title, paste the full public line and leave Allow write access unchecked.

  4. Verify access before cloning

    sudo -u "$SITE_USER" -H env   GIT_SSH_COMMAND="ssh -i $SSH_DIR/<PROJECT_SLUG>_prod -o IdentitiesOnly=yes"   git ls-remote git@github.com:<GITHUB_OWNER>/<GITHUB_REPOSITORY>.git refs/heads/main

    Validate GitHub’s published SSH host fingerprint before accepting a first-time host prompt.

Key policyOne repository-specific read-only key per production project. Do not reuse a developer’s personal key, copy a private key into chat/email, or enable write access for a pull-only deployment.

Section 7

Runtime and process rules

Node applications

Default to Node.js 22 LTS. Use the lockfile and pinned package manager. Bind production servers to 127.0.0.1; Apache provides public access.

PHP applications

Select the approved PHP-FPM version in ISPConfig. Serve only the framework’s public directory. Use Supervisor for persistent workers and ISPConfig cron for schedules.

Python applications

Use a project-owned virtual environment inside the application tree, a production WSGI/ASGI server on loopback and Supervisor for persistence.

All runtimes

Processes run as the ISPConfig site user, never root. Logs have project-specific paths. Configure clean stop, automatic restart and startup recovery.

Supervisor template

[program:<PROJECT_SLUG>-<SERVICE>]
directory=/var/www/clients/<CLIENT_ID>/<WEB_ID>/web/<PROJECT_SLUG>/source
command=<ABSOLUTE_START_COMMAND>
user=<SITE_USER>
environment=<NON_SECRET_RUNTIME_FLAGS>
autostart=true
autorestart=true
startsecs=8
stopasgroup=true
killasgroup=true
stdout_logfile=/var/log/<PROJECT_SLUG>/<SERVICE>.log
stderr_logfile=/var/log/<PROJECT_SLUG>/<SERVICE>-error.log

Section 8

ISPConfig web-engine requirements

One-engine ruleSet WEB_ENGINE=apache or WEB_ENGINE=nginx. The generated runbook must include and execute only the matching track; never bind both engines to public ports 80/443 unless infrastructure engineering explicitly designed that topology.
  • Create DNS before requesting Let’s Encrypt.
  • Create exact hostnames under ISPConfig Sites → Website.
  • Enable SSL, Let’s Encrypt and HTTP-to-HTTPS redirection.
  • Disable directory listing, CGI, SSI and WebDAV unless explicitly required.
  • Apply custom rules through the selected engine’s ISPConfig directives/templates only.
  • Do not expose application ports publicly.
  • Preserve the original host and forward HTTPS scheme information.
  • Validate the selected engine with apachectl configtest or nginx -t before reload.

Apache reverse-proxy pattern

ProxyPreserveHost On
RequestHeader set X-Forwarded-Proto "https"
ProxyPass        / http://127.0.0.1:<APP_PORT>/ retry=0 timeout=120
ProxyPassReverse / http://127.0.0.1:<APP_PORT>/

Source protection pattern

<Directory "/var/www/clients/<CLIENT_ID>/<WEB_ID>/web/<PROJECT_SLUG>">
  Require all denied
</Directory>

Nginx reverse-proxy pattern

location / {
  proxy_pass http://127.0.0.1:<APP_PORT>;
  proxy_http_version 1.1;
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Forwarded-Proto $scheme;
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";
}

location ~ /(?:\\.git|\\.env|node_modules|logs?)(?:/|$) {
  deny all;
  return 404;
}
Framework-specific adjustmentThe generated template must reconcile the denial rule with the application’s serving model. A pure Apache/PHP app may instead set its document root to the approved public subdirectory. A proxied Node/Python app can deny direct filesystem serving and proxy all requests.

Section 10

Required release lifecycle

Collect oncePreflightBackupFetch tagsCheckout approved tagLocked installBuildMigrate onceRestartSmoke testRecord evidence

  1. Collect once

    Run the complete diagnostic bundle in Section 15 and return the entire marked output in one message. Do not troubleshoot individual commands before the baseline is collected.

  2. Preflight

    Confirm clean working tree, disk/RAM, runtime versions, directory ownership, writable caches, DNS, TLS readiness, data connectivity, secret-name completeness, database role capabilities and rollback tag. A failed preflight is a STOP; no install, build or migration may begin.

  3. Deploy exact release

    Use an annotated approved tag. Record tag and commit SHA. Do not deploy a moving branch or develop on production.

  4. Migrate safely

    Back up first, run the release migration command once and prohibit destructive demo/seed commands in production. Server-level role creation must be performed during database provisioning, not discovered midway through an application migration.

  5. Verify end-to-end

    Test health endpoints, authentication, authorization, primary business workflow, uploads/email where applicable, restart recovery and absence of deferred services.

  6. Rollback

    Document application rollback separately from data restoration. Never reverse destructive schema changes casually; validate backups outside production first.

Section 11

What the deployment-template AI must produce

  • Rich-text HTML runbook suitable for browser viewing and printing.
  • A values table separating confirmed values from unresolved placeholders.
  • One initial diagnostic command block that collects the full non-secret baseline, with clear BEGIN/END markers.
  • A single consolidated assessment of all detected blockers, ordered by dependency, rather than one-error-at-a-time troubleshooting.
  • Stop/go gates for missing domains, access, secrets, storage, email, backup and dates.
  • Every command block must state: who runs it, expected success evidence, failure stop condition and the next command if successful.
  • Exact GitHub public deploy-key generation, handoff and verification commands.
  • ISPConfig website creation, DNS, TLS and managed Apache or Nginx instructions selected by WEB_ENGINE.
  • Correct web-tree application path and protected private-tree secrets path.
  • Runtime package, locked dependency, build and start commands.
  • Supervisor definitions for each persistent service.
  • Database/cache/object-storage provisioning with private network boundaries and an explicit privilege matrix.
  • Pre-deployment backup and isolated restore proof.
  • Health, security and full business-workflow acceptance matrix.
  • Update procedure, clean-tree rule and rollback procedure.
  • Final launch checklist and evidence-return list.
  • No real credentials, private keys or invented infrastructure values.
Anti-ping-pong ruleThe AI must not respond to a routine failure with only one speculative next command. It must use the returned diagnostic bundle, identify likely downstream blockers, and provide a bounded phase containing validation, correction and verification. If additional evidence is genuinely required, request all related non-secret evidence in one command block.

Section 14

Single-round-trip WhatsApp handoff protocol

This protocol is mandatory when one person runs commands on the server and passes terminal output to an AI or remote engineer through WhatsApp.

Operator sends once

Send the project runbook, completed intake values and the complete output from Section 15. Preserve BEGIN/END markers and exit codes. Use a text file when the output is too large for one message.

AI assesses once

Review the entire baseline before prescribing changes. Return all detectable blockers in dependency order: identity and paths, permissions, tools, data services, build, migration, process manager, proxy, TLS and acceptance.

Bounded phases

Each phase has one state-changing objective followed immediately by verification. Do not continue after a STOP result or mix provisioning, migration and public cutover in one unverified block.

Safe evidence

Return output, exit status and relevant log excerpts. Never return passwords, private keys, complete environment files, database dumps, tokens, cookies or personal records.

Required message format

PROJECT: <PROJECT_NAME>
SERVER: <HOSTNAME>
PHASE: <PREFLIGHT | PROVISION | BUILD | MIGRATE | START | PROXY | ACCEPTANCE>
RELEASE: <TAG AND COMMIT>
RESULT: <PASS | STOP>

--- BEGIN COMMAND OUTPUT ---
[paste complete marked output]
--- END COMMAND OUTPUT ---

CHANGES SINCE LAST MESSAGE:
- [brief non-secret summary, or NONE]
Redact before sendingReplace password and token values with [REDACTED]. Do not redact variable names, usernames, hostnames, ports, paths, role attributes, ownership modes, status codes or error messages; those are required for diagnosis.

Section 15

One-shot non-secret preflight bundle

Run this before the first deployment command and after a material server rebuild. It is read-only. Set project variables first; never paste secret values into this block.

set -u
: "${APP_ROOT:?Set APP_ROOT}"
: "${SITE_USER:?Set SITE_USER}"
CACHE_ROOT="${CACHE_ROOT:-$APP_ROOT/.cache}"
SOURCE_ROOT="$APP_ROOT/source"
section() { printf '\n===== %s =====\n' "$1"; }
run() { printf '+ %s\n' "$*"; "$@"; rc=$?; printf '[exit=%s]\n' "$rc"; return 0; }

printf '%s\n' '--- BEGIN SUNISLE PREFLIGHT ---'
section IDENTITY
run date -Is
run hostname -f
run id
run id "$SITE_USER"
run getent passwd "$SITE_USER"

section PLATFORM
run sh -c 'cat /etc/os-release | grep -E "^(PRETTY_NAME|VERSION_ID)="'
run uname -a
run df -h "$APP_ROOT"
run df -i "$APP_ROOT"
run free -h

section PATHS_AND_PERMISSIONS
run namei -l "$APP_ROOT"
run namei -l "$SOURCE_ROOT"
run namei -l "$CACHE_ROOT"
run sudo -u "$SITE_USER" test -r "$SOURCE_ROOT/package.json"
run sudo -u "$SITE_USER" test -w "$APP_ROOT"
run sudo -u "$SITE_USER" test -w "$CACHE_ROOT"

section TOOLCHAIN
run node --version
run corepack --version
run sudo -u "$SITE_USER" -H env COREPACK_HOME="$CACHE_ROOT/corepack" PNPM_HOME="$CACHE_ROOT/pnpm" pnpm --version
run git --version
run psql --version
run supervisorctl version

section SOURCE
run sudo -u "$SITE_USER" -H git -C "$SOURCE_ROOT" status --short --branch
run sudo -u "$SITE_USER" -H git -C "$SOURCE_ROOT" rev-parse HEAD
run sudo -u "$SITE_USER" -H git -C "$SOURCE_ROOT" describe --tags --exact-match
run sudo -u "$SITE_USER" -H git -C "$SOURCE_ROOT" remote -v

section ENVIRONMENT_NAMES_ONLY
if test -r "$APP_ROOT/shared/.env"; then ENV_FILE="$APP_ROOT/shared/.env"; elif test -r "$SOURCE_ROOT/.env"; then ENV_FILE="$SOURCE_ROOT/.env"; else ENV_FILE=""; fi
if test -n "$ENV_FILE"; then printf 'Environment file found: %s\n' "$ENV_FILE"; sed -n 's/^\([A-Za-z_][A-Za-z0-9_]*\)=.*/\1=[SET]/p' "$ENV_FILE" | sort; else printf '%s\n' 'Environment file not found [STOP]'; fi

section LISTENERS_AND_SERVICES
run ss -lntp
run systemctl --no-pager --failed
run supervisorctl status

section WEB_ENGINE
run sh -c 'command -v apachectl && apachectl configtest'
run sh -c 'command -v nginx && nginx -t'

section RECENT_ERRORS
run journalctl -p err -n 80 --no-pager
printf '%s\n' '--- END SUNISLE PREFLIGHT ---'
Interpret the bundle as a wholeSome probes may return non-zero when a component is intentionally absent, such as Nginx on an Apache server. The receiving AI must compare results with WEB_ENGINE; the operator must not repair every non-zero line independently.
Preflight GO ruleProceed only when the runtime is pinned, the site user can read the checkout and write the approved cache, source is at an approved tag, required environment names exist, database capabilities pass, required data services are reachable and rollback evidence exists.

Section 16

Database privilege gate before migration

Database provisioning and application migration are separate phases. Inventory all migration files for CREATE ROLE, ALTER ROLE, BYPASSRLS, extensions and database-level grants before deployment. Put server-level administration in a one-time DBA provisioning script rather than discovering it during application migration.

ConnectionPurposeExpected capabilityForbidden use
MIGRATION_DATABASE_URLSchema migrationsOwn/create schema objects and policies; server-level capability only when approvedNormal application traffic
DATABASE_URLTenant runtimeLeast-privilege DML under RLSDDL, role creation or RLS bypass
PUBLIC_DATABASE_URLPublic readsSELECT on approved views/tablesPersonal base tables or writes
PLATFORM_DATABASE_URLAuthorized cross-tenant operationsExplicit grants and approved BYPASSRLSGeneral administration or migrations

Safe capability report

Run with the deployment environment loaded. It reveals identities and capabilities, not passwords.

printf '%s\n' '--- BEGIN DATABASE PREFLIGHT ---'
for url_name in MIGRATION_DATABASE_URL DATABASE_URL PUBLIC_DATABASE_URL PLATFORM_DATABASE_URL; do
  eval 'url=${'"$url_name"':-}'
  printf '\n===== %s =====\n' "$url_name"
  if test -z "$url"; then printf '%s\n' 'NOT SET [STOP if required]'; continue; fi
  psql "$url" -X -v ON_ERROR_STOP=1 -Atc "SELECT 'identity='||current_user||',database='||current_database(); SELECT 'capabilities=super:'||rolsuper||',createrole:'||rolcreaterole||',createdb:'||rolcreatedb||',bypassrls:'||rolbypassrls FROM pg_roles WHERE rolname=current_user;" || printf '%s\n' 'CONNECTION FAILED [STOP]'
done
printf '\n===== REQUIRED APPLICATION ROLES =====\n'
psql "$MIGRATION_DATABASE_URL" -X -v ON_ERROR_STOP=1 -P pager=off -c "SELECT rolname, rolcanlogin, rolsuper, rolcreaterole, rolbypassrls FROM pg_roles WHERE rolname IN ('gameday_app','gameday_public','gameday_platform') ORDER BY rolname;"
printf '%s\n' '--- END DATABASE PREFLIGHT ---'
Migration STOP conditionsStop if the migration identity is unknown or lacks required DDL ownership; a runtime role is absent; gameday_platform lacks its approved RLS capability; a runtime role is unexpectedly superuser or has CREATEROLE; backup is unverified; or the release migration inventory has not been reviewed.

Receiving-AI response obligation

Return one consolidated matrix with PASS, STOP or NOT APPLICABLE for filesystem, toolchain, source, environment names, PostgreSQL, Redis, object storage, Supervisor, selected web engine, DNS/TLS, backup and rollback. Only then provide the next bounded command phase.
