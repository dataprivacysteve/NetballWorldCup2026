Chapter 1

Purpose and authority

SportsBB owns the reusable GameDay chassis and the event-level contract consumed by registration, accreditation, competition operations, the public website and broadcast feeds.

Authority boundaryOnly the sportsbb_admin account may enter the SportsBB control plane. LOC credentials are deliberately denied. Never share this account with the LOC, teams, gate staff or GameDay officials.

SportsBB is accountable for

Event governance

Tournament identity, dates, timezone, registration window, eligibility date, countries, roster policy, document policy, official roles and accreditation zones.

Digital service

Production domains, certificates, databases, object storage, email integration, backups, monitoring, incident response and support escalation.

Public and commercial content

Official logos, hero content, tickets, merchandise, partners, advertisements, newsroom entries and public recovery messaging.

Controlled handoff

Publish a validated configuration, give the LOC the operational boundaries it needs, and retain control of policy and commercial content.

SportsBB does not perform

  • Manual review of team passports or national IDs.
  • Delegation approval, roster accreditation or badge decisions.
  • Routine fixture entry, GameDay staffing or match scoring.
  • Coaching decisions or assignment of players to match positions.

Chapter 4

Sign in securely

  1. Open https://platform.netballamericas.org/control. Use the .test equivalent only for local UAT.
  2. Confirm the browser displays a valid TLS padlock and the exact production hostname.
  3. Enter the SportsBB administrator email and password supplied through the approved secure channel.
  4. Select Enter control plane. Confirm the header identifies you as Platform Administrator.
  5. If the screen says “SportsBB administrator only,” sign out; the wrong account is active.
Never document production passwords hereStore them in the approved secret/password manager. Rotate local/UAT credentials before any external user is admitted.

Chapter 5

Configure the event contract

The control plane saves changes as a new draft version. Treat the form as a governed contract: one incorrect value can affect several downstream modules.

5.1 Event identity

  1. Enter the formal Tournament name exactly as approved.
  2. Enter the Short name used on compact screens and public components.
  3. Set an IANA timezone such as America/Barbados. Do not use a fixed UTC offset.
  4. Set tournament Starts and Ends dates.
  5. Set the fixed Eligibility date. Confirm it against the relevant regulations before publishing.
  6. Set Registration opens and Registration closes. Recheck the displayed local time and the corresponding UTC value.

5.2 Roster policy

FieldQualifier baselineEffect
Active minimum10Roster cannot be submitted below this number.
Active maximum15Maximum active players.
Reserve maximum3Up to three travelling reserves.
Bench maximum17Match bench allocation across players and officials.
Biography minimumConfigured valueMinimum player biography characters enforced at submission.

5.3 Team officials and evidence policy

  1. Select required official roles: normally Team Manager, Coach and Primary Care.
  2. Use “Other” only if event policy requires an additional named role. The roster supports up to two additional officials.
  3. Select the person categories requiring identity evidence. For the agreed qualifier policy, players require passport or national ID; officials do not automatically inherit that requirement.
  4. Select categories subject to guardian consent. The server applies age/category rules; do not substitute an informal checkbox.
  5. Enter the full eligibility-regulation reference. This text supports the declaration where a player’s nationality differs from the represented team.
Closing date behaviorAfter registration closes, no new team may register. Existing approved team accounts retain roster amendment access. A material personnel, identity, eligibility, classification or accreditation change returns the roster to LOC review and revokes affected live credentials.

Chapter 6

Maintain eligible countries

  1. In the control plane, scroll to the eligible-country manager.
  2. Compare the displayed list with the signed eligibility list.
  3. Add each country using its approved three-letter code and public name.
  4. Use the active/inactive control rather than changing a country code after teams have registered.
  5. Before publishing, verify there are no duplicates and that every invited country is selectable in registration.
Data relationshipCountry configuration governs new delegation intake. It does not itself approve a delegation; the LOC still performs the operational registration decision.

Chapter 7

Brand and accreditation

7.1 Official event graphics

  1. Use the official NWC Sydney 2027 Regional Qualifier Americas artwork. Never substitute the former generic Netball Americas image.
  2. Set the Primary logo asset path to the approved positive artwork for light backgrounds.
  3. Set the Reverse logo asset path to the approved negative artwork for dark backgrounds.
  4. Confirm the primary preview is sharp, undistorted and complete.
  5. Open the Platform, Team Portal and public site at desktop and mobile widths to confirm the official artwork appears correctly.

7.2 Access-zone matrix

  1. Prepare valid JSON mapping each accreditation category to its allowed zones.
  2. Use exact zone names approved for signage and access control.
  3. Paste the JSON into Access-zone matrix.
  4. Save the draft. If parsing fails, correct commas, quotation marks and array brackets.
  5. Generate sample badges after publication and confirm the expected zones appear.
Do not casually change zones after credentials are issuedAssess whether badges must be revoked and reissued. Record the approved change and inform the LOC before applying it.

Chapter 8

Version, publish and lock

Save a draft

  1. Complete the configuration form.
  2. Select Save as new draft version.
  3. Resolve any validation error; do not refresh until the save succeeds.
  4. Review the Publish readiness panel.

Publish

  1. Run the pre-publication checklist with a second reviewer.
  2. Select Publish version.
  3. Confirm the status chip displays Published with the expected version.
  4. Test Team Portal registration rules and the public surfaces.

Lock

  1. Lock only after policy sign-off and successful UAT.
  2. Select Lock configuration.
  3. Confirm the form becomes read-only and the button indicates Configuration locked.
  4. Record the locked version in the launch sign-off.
Lock is a governance actionDo not use it as a casual save button. If a post-lock policy correction is required, follow formal change and incident control.

Chapter 9

Configure the public website

Open /control/public or select Public experience from the SportsBB header.

  1. Enter the approved Hero image URL. Use a production asset location over HTTPS.
  2. Enter the Hero strapline; check spelling, competition naming and tone.
  3. Enter the Ticket destination and test it in a separate private/incognito window.
  4. Enter the Merchandise destination and Merchandise image URL.
  5. Enter the monitored Public contact email.
  6. Enter approved About the qualifier copy.
  7. Set the Delayed live-update message. Use neutral language that does not speculate about the cause.
  8. Select Save public configuration.
  9. Open the public site and verify every image, link and text block.

Chapter 10

Partners and advertising

Managed service boundaryCommercial content remains exclusively a SportsBB responsibility. The LOC does not upload or manage sponsors or advertisements.

Current partner placement behavior

SilverFirst bannerUses the supplied logo and destination.
BronzeSecond bannerUses the supplied logo and destination.
SupporterPartner-logo sectionDisplayed with the wider active partner list.

Add a partner

  1. Obtain written approval for the partner name, tier, artwork and destination.
  2. Validate the artwork: correct brand, adequate resolution, safe margins and permitted file format.
  3. Upload the approved file to the production content/asset service. The current form accepts a URL; it does not upload the file itself.
  4. Enter Partner name.
  5. Select the correct Tier.
  6. Paste the HTTPS Logo URL and the approved Destination URL.
  7. Select Add partner.
  8. Verify the expected website slot, desktop/mobile rendering and destination behavior.

Remove or replace a partner

  1. Record the approval or expiry instruction.
  2. Use Remove beside the current entry.
  3. For replacement, add the newly approved record and recheck the placement.
  4. Clear CDN/browser caches only through the approved service procedure; never edit page code.
Current management limitationThe implemented screen adds and removes partner records. It does not yet provide direct uploads, editing, scheduled start/end dates, rotating campaigns, creative-specific placement controls or analytics. Until those controls are developed, SportsBB must operate the asset URL and publication process as a managed service.

Chapter 11

Operate the newsroom

  1. Obtain approved headline and summary text.
  2. Enter the Headline. The platform derives a stable slug.
  3. Enter the Summary.
  4. Leave Publish immediately unchecked for a draft; select it only after approval.
  5. Select Add article.
  6. Confirm the status is Draft or Published as intended.
  7. Open the public website and verify the visible entry.
  8. Use Remove only with editorial approval.

Chapter 12

Registration readiness

Before opening

  • Published version contains the correct opening/closing timestamps.
  • All eligible countries are active.
  • Roster and official limits match the signed requirements.
  • Player identity evidence policy is enabled.
  • Official event logo appears on Team Portal.
  • Password-recovery email delivery is proven.
  • LOC officer can access review surfaces but cannot enter SportsBB control.
  • Test team can complete registration, roster, document upload and submission.

At opening time

  1. Confirm production monitoring is green.
  2. Open Team Portal in a private browser window.
  3. Verify new-team registration is available.
  4. Register a controlled test delegation only if the launch plan permits it.
  5. Confirm the LOC sees the submitted registration.
  6. Record launch time and result in the operations log.

At closing time

  1. Verify a new unauthenticated team cannot begin registration.
  2. Verify an existing approved team can still sign in and amend its roster.
  3. Confirm material amendments reopen LOC review and revoke affected credentials.
  4. Notify the LOC that no new teams will enter the intake queue.

Chapter 13

Accounts and security

  • Use one named SportsBB administrator account; do not create a shared “admin” mailbox login.
  • Use a minimum 12-character unique password and approved password manager.
  • Distribute credentials through a secure channel, never email or this manual.
  • Rotate UAT/default passwords before external access.
  • Use password reset rather than revealing an existing password.
  • Revoke all sessions after suspected compromise or staff departure.
  • Review attributed audit events during launch and after critical changes.
  • Never use the migration/superuser database credential for runtime services.
Database separationProduction uses separate application, Platform operations, public read-only and migration connections. The public role must not read private user, registration or identity tables.

Chapter 14

UAT and launch approval

Required rehearsal

  1. Use the August 1 full-test window or an approved replacement date.
  2. Exercise one delegation from registration through roster approval and credentials.
  3. Configure a neutral Team A/Team B fixture.
  4. Assign all five GameDay roles.
  5. Submit both match sheets and complete a four-quarter rehearsal.
  6. Record goals, corrections, substitutions, statistics and an incident.
  7. Suspend/resume, reconcile paper and electronic records, then confirm the result.
  8. Test the gate online, offline, reconnect and verify deduplicated audit records.
  9. Test public live score delay/recovery and broadcast XML/JSON refresh.
  10. Record SportsBB, LOC, venue technical and broadcast sign-off.

Launch gate

Pass only whenEvery production build is deployed; migrations are applied; backups restore; email works; all roles are isolated; official branding is correct; and the complete operational rehearsal has no unresolved severity-one or severity-two defect.

Chapter 15

Daily service operations

Start-of-day

  • Check Platform, Team Portal, public website and API health.
  • Check database, object storage and email service health.
  • Review failed logins, application errors and storage alerts.
  • Confirm scheduled backups completed.
  • Check public content and commercial destinations.
  • During competition, confirm broadcast feeds and optional venue-edge status.

During service

  • Keep an incident log with timestamps, impact and owner.
  • Do not make policy changes directly in production without approval.
  • Use the delayed-update message if public scores are temporarily unavailable.
  • Coordinate operational issues with the LOC without granting SportsBB access.
  • Preserve logs and audit evidence for material incidents.

End-of-day

  • Confirm all scheduled matches are final or explicitly suspended/postponed.
  • Confirm result approvers completed reconciliation.
  • Review outstanding registration/credential exceptions with the LOC.
  • Verify backups and record restoration point.
  • Publish an internal daily status note.

Chapter 16

Change and incident control

Change procedure

  1. Record the requested change, owner, reason, affected modules and deadline.
  2. Classify it as content, operational data, policy or infrastructure.
  3. Obtain the correct approval.
  4. Test in the UAT environment.
  5. Schedule the production change and notify affected operators.
  6. Take/verify a rollback point.
  7. Apply the change and run targeted smoke tests.
  8. Record result, version and any follow-up.

Incident priorities

PriorityExampleImmediate response
P1Registration unavailable at launch; scoring unavailable during a live match; data exposure.Declare incident, assign lead, preserve evidence, invoke continuity procedure and communicate.
P2One major workflow degraded; broadcast/public feed materially delayed.Workaround, targeted recovery, stakeholder update and tracked correction.
P3Minor content/display issue with no operational block.Log, prioritize and correct through normal change control.

Chapter 17

Handoff to the LOC

  1. Publish and, when approved, lock the event configuration.
  2. Provide the LOC with event dates, registration window, roster/document policy, access zones and escalation contacts.
  3. Create or verify the single named LOC officer account.
  4. Confirm LOC access to operations, accreditation, fixtures, staffing, venue and broadcast areas.
  5. Demonstrate that LOC credentials cannot enter /control or /control/public.
  6. Complete one delegated workflow together from submitted team to issued credential.
  7. Agree support channels and incident severity definitions.
  8. Record formal handoff and outstanding dependencies.

Chapter 18

Production configuration

This chapter begins when servers, DNS, certificates, databases, storage, email and broadcast services are available.

Cloud environment

  • Set NODE_ENV=production.
  • Configure separate runtime, Platform, public-read and migration database URLs.
  • Configure strong JWT/session settings and production cookie domain.
  • Set API and public-site production origins.
  • Configure S3/MinIO endpoint, credentials and photo/identity buckets.
  • Configure password-recovery webhook, sender and support details.
  • If using venue standby, configure a strong edge synchronization secret.
  • Apply migrations through 0027_edge_public_broadcast.

Optional venue environment

  • Register a venue node in the LOC venue-resilience screen.
  • Provision a trusted venue server and local database.
  • Set runtime mode to edge, node ID, secret, cloud origin and local origin.
  • Provision assigned GameDay identities and scoped match data using the authoritative bootstrap manifest.
  • Install process supervision and automatic restart.
  • Disconnect/reconnect internet during a full rehearsal and reconcile ledger versions.

Chapter 20

Master checklists

Configuration sign-off

  • Event identity and timezone verified.
  • Registration/eligibility dates approved.
  • Countries and roster policy verified.
  • Officials, identity and consent policy verified.
  • Official positive and negative logos verified.
  • Access-zone JSON validated.
  • Public content and commercial links checked.
  • Draft reviewed by a second person.
  • Version published and recorded.
  • Lock approval recorded.

Production go-live

  • DNS/TLS and all four public services healthy.
  • Database roles separated and migrations applied.
  • Object storage and email proven.
  • Backups restored successfully in a clean environment.
  • All UAT/default passwords rotated.
  • LOC handoff and role isolation proven.

  • Gate offline/reconnect passed.
  • Broadcast feeds and public recovery state passed.
