  • BTMI lead-partner animated banner and official logo, both linking to Visit Barbados; privacy page; footer layout changes; removal of public ticket, travel and venue promotions.
  • Pending player-photo governance, withdrawal controls and roster-photo publication; official/rehearsal separation and public fixture date filtering.

1. Identify the installation and record the current services

Actor: root or the existing authorised deployment administrator, in a Bash shell on the live Debian server. Keep this shell open. Run blocks in order and stop on an error. Parenthesised blocks use a subshell so an error does not log you out.

A read-only host inventory script is supplied beside this guide. Run it on the target host with the established site identity and review its output locally. It does not replace the service-specific checks below. No fresh host inventory was available when this guide was authored.

Schedule a brief deployment window before a match starts. Have LOC staff stop account, roster and score edits; stop or pause any venue edge-sync writer using its documented procedure. Record active worker names for restart. Do not stop unrelated sites or the shared database. The DBA must have a recoverable backup and enough free space. 11. Recovery if a service fails

If API calls fail, the website goes blank or Supervisor reports BACKOFF/FATAL, keep the event write pause and inspect the affected program’s logs using its verified name:

supervisorctl status "$API_SERVICE" "$WEB_SERVICE" "$PLATFORM_SERVICE"
supervisorctl tail "$API_SERVICE" stderr
supervisorctl tail "$WEB_SERVICE" stderr
supervisorctl tail "$PLATFORM_SERVICE" stderr
SymptomFirst action
404 at /public/match-centreConfirm API service directory/command and RELEASE_COMMIT. Do not fix only the website.
“Column does not exist” or missing photo viewCheck the actual live migration ledger and database identity; resolve pending 0042/0043. Do not seed or manually fabricate migration history.
Browser tries a .test host / CORS errorCorrect new-release URL settings and conflicting overrides; rebuild the affected Next app, then restart it.
Public results stop changingInspect network errors/cache headers and API logs. Check that the game is official and Final confirmation occurred. A hidden tab deliberately pauses polling.
Portrait missingCheck LOC release status, individual withdrawal, approved roster and usable latest JPEG. Do not expose a private storage bucket.
Permission denied / Next cannot startConfirm site-user ownership/traversal, runtime path, built app artifacts, working directory and actual port availability.

Application rollback: restore the backed-up Supervisor configuration for all three updated services, preserving each one’s actual old release/command; restore a shared symlink only if that was the verified deployment mechanism. Run supervisorctl reread, supervisorctl update for those specific programs, and restart them. Confirm old API/site/login health before resuming writes. Keep the new release and logs for diagnosis.

Database rollback: leave the additive publication tables/columns/views in place for a normal application rollback. An earlier application may still observe changed public-view behaviour; have the LOC review image-publication status and, if required, disable publication using the new Player images control before rolling back. A full database restore is a DBA-led recovery operation requiring a controlled outage and reconciliation of any writes after the backup. Never overwrite an advancing live database to undo a UI problem, and never drop the new tables as an improvised rollback.

Keep both old and new builds, the protected configuration backup and the database recovery point until the event’s deployment owner accepts the update. Do not delete release directories or alter unrelated hosted services during this handoff.
